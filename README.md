# dsh-branch-hover

DSH 插件：把「这段代码属于哪个市场」放到三处看得见的地方——会话行 hover 卡片、
新建的空白会话、以及每一轮回答的下方。分支名前段能认出客户编码（`KH000115`）时，
一并显示对应的银行名。

## 效果

### 1. 会话行 hover：当前分支 + 市场（实时）

hover 会话行，卡片里多出分支行，认得出客户编码时再跟一行市场名：

```
⎇ KH000115-无纸化信创(2.3_20160627) ↑2
市场：宁夏银行
```

- `⎇` 正常分支；`⑂` detached HEAD
- `↑N` 领先上游 N 个提交，`↓N` 落后 N 个，`●N` 有 N 个未提交改动
- 三项都为 0 时不显示（保持卡片干净）
- 市场行显示**客户简称**，鼠标停在上面时的提示里给「客户编码 + 全称」
- 认不出客户编码的分支（`master` / `others` / `范菲菲(2.6_20170324)…`）不显示市场行
- 不是 git 仓库 → 整块不渲染

### 2. 新建的空白会话：当前市场（一条全宽提示行）

在工作区里新建会话、还没发出第一条消息时，输入框正上方多一条居中的小字：

```
              市场：宁夏银行
```

发出第一条消息后（会话不再是空白）这行就收起来，不长期占用界面。

### 3. 每一轮回答的下方：**该轮当时**的分支 + 市场（定格，不随切换变化）

```
⎇ KH000456-柜面升级改造项目(2.7.1_20171207) · 北农商
```

这条信息属于**那一轮**：它记录的是「这一轮开始时工作区在哪个分支」，之后你在同一个
工作区切到别的分支、重开会话、甚至几个月后翻旧会话，它都不会变——避免回溯时把某轮
对话针对的代码分支搞混。不是 git 仓库、或认不出当时的分支时，这一行不渲染。

推算法（按 `at` 时刻回放，见下）：
- 依据是 git reflog 里 **checkout 条目自身的墙钟时间**，取「该时刻之前最后一次切换」的目标分支
- 该时刻早于 reflog 里全部切换 → 用**最早那次切换的 from**（切换前所在的分支），标记为推断
- reflog 里一条切换都没有（例如这个 clone 从没换过分支）→ 用当前分支，标记为推断；
  鼠标停在那一行时的提示里会注明「按 reflog 推断」
- 判不出来 → 整行不渲染（宁可没有，也不给一个编出来的分支名）

**已知边界**：reflog 是 git 的本地日志，可以被裁剪（默认 90 天）或在新 clone 里为空，
被裁剪掉的切换就推不出来了——那时的回放会退化成上面第 2/3 条规则。

## 市场名映射

分支名前段是客户编码：`KH000115-无纸化信创(2.3_20160627)` → `KH000115`。编码对应哪家
银行来自 afa 文档库的《客户信息.xlsx》，该映射在**构建期**烘焙成 `src/customers.json`
快照（运行时只读快照，不读 xlsx）：

```bash
node tools/generate-customers.mjs                 # 默认取 master 空间 doc/客户信息.xlsx
node tools/generate-customers.mjs /path/to.xlsx   # 或显式指定
```

- 列**按表头文字定位**（客户编码 / 客户名称 / 客户简称），表头换列不会悄悄错位
- 编码形态两种：`KH` + 6 位数字、内部编码 `3000-` + 8 位数字
- 编码不必在开头：`江苏KH000296-支付平台(侯江_2.5_20161216)`、`AFA4J_1.7_20150401(KH000210)`
  都能解析，取全名里第一处编码
- **doc 更新后要重跑生成器再重新构建**，否则市场名停留在旧快照

## 为什么是这三个位置

DSH 内核（`dsh-client-ui-workspace`）**没有**为工作区标题行开放装饰插槽。它只暴露了
会话行级别的席位：

| 插槽 | 本插件是否使用 |
| --- | --- |
| `sidebar.session.row.leading` | ✗（该格会被状态点顶掉，标记会时有时无） |
| `sidebar.session.row.hover` | ✓ 悬停卡片中段，稳定可见 |

工作区标题行的渲染是写死的（文件夹图标 + 标题 + hover 按钮），插件够不到那个位置，
所以「常驻在工作区行上」在当前 DSH 版本下无法实现。要覆盖「在工作区里新建会话」这个
时刻，能用的席位是新建视图里的 `conversation.input.dock`——它渲染在 hero 的工作区
chip 与输入框之间，正是用户看工作区名的地方。

## 架构

双面包（dual-face）插件：

```
src/git.js       只读 git 查询：概况（symbolic-ref / status / rev-list）
                 与历史回放 readBranchAt（reflog）
src/market.js    分支名 → 客户编码 → 市场名（读构建期快照）
src/index.js     宿主半：GET /branch-hover/api?cwd=<绝对路径>[&at=<epoch 毫秒>]
src/client.js    浏览器半：三处注册（见下表）
src/customers.json  构建期生成的客户快照（勿手改）
tools/generate-customers.mjs  xlsx → customers.json
build.mjs        构建 + 契约自检
test/host.mjs    宿主路由真跑测试（自带临时 git 仓库，含历史回放与定格断言）
test/market.mjs  编码解析真跑测试
test/render.mjs  三处界面渲染真跑测试
```

| 席位 | 组件 | 何时渲染 | 取数 |
| --- | --- | --- | --- |
| `sidebar.session.row.hover` | `BranchHover` | 悬停会话行 | 实时（不带 `at`） |
| `conversation.input.dock` | `MarketDock` | `session.blank === true` | 实时（不带 `at`） |
| `conversation.chat.turnTail` | `TurnBranch` | 每轮完成 | **历史**（`at=该轮开始时刻`） |

三处都通过 `ctx.slots.inject(...)` 注册：`slots.register` 对**未声明**的席位会抛错，
而 `inject` 的回调在席位被其宿主包声明时才运行，所以本插件的加载顺序无关紧要。

**为什么必须有宿主半**：浏览器沙箱里没有 `child_process`，读不到 git；工作区路径
也只存在于宿主侧。所以客户端从 `useSessions((l) => l.byId[sessionId]?.cwd)` 取路径，
再请求宿主路由拿 git 概况。

**为什么市场名走宿主半**：快照 883 条、约 90KB，塞进浏览器 bundle 不划算；宿主半读一次
常驻内存，客户端只多拿一个字段。`git.js` 保持只认 git，市场名在 `index.js` 里拼上去。

**历史回放为什么这么做**：浏览器只把 `at`（该轮开始时刻）传下来，判断「那时在哪个分支」
是宿主的事，依据是 reflog 里 checkout 条目自身的墙钟时间。这样：
- 刷新页面、重启、换机器后翻旧会话，这条信息不变（不像「第一次渲染时记一笔」那样一刷新全变成当前分支）
- 对插件存在之前的历史轮次同样有效（不需要提前记录过）

**性能**：宿主侧概况 4s TTL 缓存 + 在途请求合并；reflog 时间线按 cwd 缓存 30s，但
**查询时刻落在最近 60 秒内时绕过缓存重读**——刚切完分支就去回放「现在」，读旧时间线
会把新分支标成旧分支，正是要避免的混淆（绕过窗口 ≥ TTL 保证这类错误不可能发生）。
客户端侧：概况按 cwd 缓存 4s；历史回放按 `cwd + at` **长期**缓存（历史值不会变），
条目有上限。注意概况缓存按 cwd 记：同一工作区刚切过分支时，hover 里的分支名/市场名
最多滞后 4s。

## 构建

```bash
node build.mjs          # 搬运宿主半 + 包装浏览器半 + 契约自检
node test/host.mjs      # 宿主路由：市场名字段、at 历史回放、定格断言、错误码
node test/market.mjs    # 客户编码解析
node test/render.mjs    # 三处界面的渲染状态
```

`build.mjs` 会在构建期做几项「插件能否被 DSH 加载」的硬门槛自检，这些错误在运行时
只表现为插件静默不激活，很难定位：

- `dsh.client.platform === 'web'` 与 `exports["./client"]` 必须存在
  （client-modules 靠 `exports["./client"]` 定位浏览器 bundle）
- 浏览器半不得混入 `import` / `export` 语句——它被包进 CJS 外壳，只能用 `require`
- 用假的 `window.__ModuleLoader__` 真跑一遍 bundle，核对注册 id 与导出的 `apply`/`inject`
- 客户快照非空，且能用一个真实分支名（`KH000115-…`）查出结果——快照来源不对时在这里暴露

## 安装

```bash
dsh plugin --profile web add /path/to/dsh-branch-hover
```

改完代码**必须重启 `dsh web`**（宿主半与浏览器半都要）：HMR 的监听根是 profile 目录，
而本插件是通过 `link:` 链进 profile 的，真实文件在 profile 之外，宿主半的热重载够不到；
浏览器半的模块表本来就只在启动时组合。改完只重建不重启，表现是**什么都不变**。

## 已知边界

- 只在 git 仓库里的工作区显示。非仓库（含**未纳入 git 的普通目录**）不渲染任何东西。
- 工作区路径取自会话的 `cwd`；未绑定工作区的会话不显示。
- 只读：本插件不执行任何写操作（不 commit、不 checkout、不 stash、不 reset）。
- 市场名覆盖到「分支名前段是客户编码」的那部分分支：master 空间各空间实测 141 个分支里
  115 个能对上；`master` / `others` / `范菲菲(2.7.1_20171207)-…` / `正式版本(…)` 这类
  看不到编码的分支没有市场行（不猜、不倒推）。
- 市场名是构建期快照，`客户信息.xlsx` 更新后需重跑生成器 + 重建 + 重启。
- 每轮定格的准确度受 git reflog 限制：reflog 被裁剪（默认 90 天）或新 clone 里为空时，
  推不出来就退化成「最早那次切换的 from」或「当前分支」，并在提示里标注为推断；
  reflog 只有秒精度，同一秒内连续切换两次无法区分。
- 一轮进行中切换分支时，定格的是**该轮开始时刻**的分支（这不是缺陷，是「这一轮针对哪个
  分支」的定义）。
- 空白会话那条市场提示行只在 `session.blank` 为真时出现；会话有内容后不再显示。
